# 0.21.0 — Your library is safe

Status: in progress · 2026-11-26 · [roadmap entry](../../ROADMAP.md#0210--your-library-is-safe)

## Why

A reader's library lives only on their device. Before 0.21 a browser could evict it silently, a backup lost Thought Parking notes and settings, one tap on the bin deleted a text for good, and a render error left a blank screen with no way to reach the data.

## What

1. **Persistent storage.** `services/storage/persistence.ts` wraps `navigator.storage.persisted()`, `persist()` and `estimate()`. Settings get a "Your library" section: how much Plyn stores on this device and whether the browser promised to keep it.
2. **Backup v2** ([IMP-05](../../IMPROVEMENTS.md#imp-05-backup-v2)): `schemaVersion: 2` adds `thoughts` and `settings`. v1 still imports.
3. **Share sheet on phones.** "Backup" on a touch device opens the system share sheet with the `.json` file. Elsewhere, or when the share sheet can't take files, it downloads as before.
4. **Undo delete.** Deleting a text removes it at once and shows "Text deleted · Undo" for 6 seconds. There was no confirmation before 0.21.
5. **Error boundary** ([IMP-07](../../IMPROVEMENTS.md#imp-07-error-boundary)): a calm screen with "Save a backup" and "Reload".
6. **App version** at the bottom of Settings, so a reader (and a tester on a PR preview) can tell which build is open.

## Decisions

- **When to call `persist()`.** On start, once the library has at least one text, and again after the first text is saved. Chromium and Safari answer silently. Firefox shows a permission prompt, which the roadmap rules out on the main screens, so on Firefox (`'Firefox'` in the user agent, the only engine that prompts) the call happens only from a "Keep my library" button in Settings. Settings shows the same button anywhere the browser said no, because the answer can change (for example after installing the app).
- **What Settings says.** Size comes from `estimate().usage`, which includes the offline copy of the app (a few MB). Copy says "Plyn takes about X on this device", not "your texts take X". Not protected: "The browser may clear it if space runs low. A backup keeps it safe." No warning colours, no numbers about risk.
- **Settings in a backup.** Applied on import only when this device has no saved settings (`plyn_settings_v1` absent), which is exactly the "restore after wipe" case. A device that already has its own theme and font keeps them.
- **Thoughts in a backup.** Merged by `id`; an existing note wins. Nothing is ever deleted by an import.
- **Backup fixtures** (`spec/backups/`): `v1-0.18.json` (the shape every release up to 0.20 wrote) and `v2-0.21.json`. `backup.compat.test.ts` imports every file in that folder into an empty database and checks counts, offsets, bookmarks, notes and stats. New schema → new fixture, never edit an old one.
- **Share sheet detection.** `pointer: coarse` and `navigator.canShare({ files })`. Cancelling the sheet is not an error and shows nothing.
- **Undo is in memory.** The text is deleted from IndexedDB immediately and kept in component state; Undo puts the same record back (same id, offset, bookmarks). Closing the app during those 6 seconds keeps the deletion, which is what the reader did. Focus moves to the Undo button so keyboard and screen reader users can reach it.
- **Error boundary copy** comes from `currentI18n()`, not a hook, and the backup button uses the same `saveBackupFile()` as the library, which depends only on IndexedDB.
