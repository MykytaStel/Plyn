# 0.22.0 — Feels like an app

Status: shipped · 2026-11-26 · [roadmap entry](../../ROADMAP.md#0220--feels-like-an-app)

## Why

Installed on a phone, Plyn still behaved like a web page: Android back left the app in the middle of a text, the screen dimmed during a long card or while listening, iOS showed a screenshot instead of an icon, a deploy could take over an open tab, and focus stayed behind a sheet when it opened.

## What

1. **Back navigation.** The reader and every open sheet own one history entry. Back (Android gesture, browser button, iOS edge swipe) closes the top sheet, then the reader. From the library it leaves, as expected.
2. **Screen Wake Lock.** The screen stays on in the reader, with a "Keep the screen on" switch in Settings (shown only where the browser has the API). On by default.
3. **Home-screen icons** ([IMP-16](../../IMPROVEMENTS.md#imp-16-png-and-maskable-icons)): `apple-touch-icon.png` 180×180, manifest PNGs 192 and 512 (`any`) and a separate 512 `maskable`.
4. **Updates that wait** ([IMP-15](../../IMPROVEMENTS.md#imp-15-service-worker-updates)): a new version installs in the background; the library shows "A new version of Plyn is ready. It opens next time you come back." with "Update now". The reader never shows it.
5. **Focus in sheets.** Focus moves into a sheet when it opens, Tab stays inside, and focus returns to the button that opened it.

Under the hood: `ReaderView` split into hooks ([IMP-08](../../IMPROVEMENTS.md#imp-08-split-readerview)); Vite 8, `@vitejs/plugin-react` 6, `vite-plugin-pwa` 2, `lucide-react` 1 ([IMP-03](../../IMPROVEMENTS.md#imp-03-dependency-hygiene)); the visual regression baseline (TESTING.md L9).

## Decisions

- **Order of work.** Visual baseline first, then the `ReaderView` split (journeys and snapshots unchanged), then features, then upgrades, each checked against the baseline.
- **Back stack** (`services/navigation/backStack.ts`). Each layer pushes `{ plynLayer: depth }`. Back pops the entry and the stack calls the top layer's `onBack`. A layer closed by the UI (close button, Escape, a row in "⋯") calls `history.go(-n)` and the popstate it causes is ignored, so no stale entries pile up. Closing one sheet and opening another in the same tap (tools → bookmarks) keeps one entry per open layer even before the browser runs the `go`. After a reload with layers open, the stack steps back to the base entry, so the first back press is never a silent one. Components use `useBackLayer(open, onBack)`.
- **What is a layer.** The reader; any reader sheet (one layer for whichever is open, so "⋯" → bookmarks is one step back); any library sheet; onboarding (back = skip, like Escape). Zen mode and the scrubber are not layers: back from them goes to the library, which is what a reader in zen mode asked for.
- **Focus** (`features/shared/useDialogFocus.ts`). The opener is read during the first render, before an `autoFocus` field (Thought Parking) takes focus. A sheet opened from another sheet inherits that sheet's opener, so closing bookmarks after "⋯" returns to "⋯", not to a removed row. Focus is restored with `preventScroll`, so the card feed does not jump.
- **Wake Lock** (`services/screen/wakeLock.ts`, `useKeepScreenOn`). Held while the reader is open and the page visible; taken again on `visibilitychange`; released in the library and after 10 minutes without a new card, a touch or a key, unless read-aloud is on. Refusals (battery saver) are silent. A switch, not a prompt: most readers want it, and the setting is in Settings only (roadmap rule 1).
- **New setting.** `keepScreenOn` is added to `UserSettings` with a default, under the same key `plyn_settings_v1`: stored settings are merged over defaults, and `parseSettings` ignores unknown fields, so 0.21 reads 0.22 settings and the other way round. Backup schema stays 2 for the same reason; `backup.compat.test.ts` now expects defaults for fields newer than a fixture (fixtures are not edited).
- **Service worker.** `registerType: 'prompt'`, `injectRegister: false`, registered in `services/pwa/registerApp.ts`. `clientsClaim: true` keeps "offline after the first visit": a first install has nothing to wait for, a later version still waits (no `skipWaiting`). "Update now" sends `SKIP_WAITING` and reloads on `controllerchange`; the plugin reloads only for updates found by workbox-window itself, not for ones the browser found later, so this listener is ours. Installed apps check for an update when they come back to the foreground, at most hourly.
- **Lazy chunks after a deploy.** A waiting worker keeps the old precache, so a long-open tab still loads its chunks. Without a worker (first visit, private mode) a chunk can be gone: `importWithRetry` tries once more, then shows `app_updated` ("Plyn has been updated. Reload the page and it will open.") instead of a generic error.
- **Icons** are rendered from `icon.svg` by `scripts/generate-icons.mjs` (Playwright), committed as PNGs. Maskable: full-bleed background, drawing at 78 % (inside the 80 % safe circle). `purpose: 'any maskable'` on one image is gone.
- **Upgrades.** `vite-plugin-pwa` 0.21 accepts only Vite ≤ 6, so Vite, plugin-react and the PWA plugin moved in one commit. `npm install` could not resolve plugin-react 6 against the old lock (an optional Babel 8 peer chain); a clean resolution works, so the three were uninstalled and installed again. Build time went from ~3.5 s to ~0.3 s; the main chunk is about 5 kB smaller (gzip).

## Findings

- **The "update now" reload.** The first version relied on the plugin's reload, which did not fire for an update found by `registration.update()`. Found by the update journey.
- **Prompt mode and offline.** Without `clientsClaim` the first visit would not be controlled until a reload, and CUJ-5 would time out. Kept by design, covered by CUJ-5.
- **Duplicate precache entries.** `includeAssets` repeated files already matched by `globPatterns`; removed.
- **Flaky CUJ-2 on Pixel** (carried from 0.21): not reproduced in 110 runs of CUJ-2, 3 and 9 with 8 workers. The 0.21 progress fix may have been the cause; the CI retry stays.
