# 0.20.0 — Safety net II: end-to-end and accessibility

Status: shipped · 2026-11-26 · [roadmap entry](../../ROADMAP.md#0200--safety-net-ii-end-to-end-and-accessibility)

## Why

0.19 tests the logic and the storage, but nothing checks that a reader can actually open Plyn in a browser, read, come back and find their place, or that the app still works offline after a deploy. Every one of those journeys was checked by hand, or not at all. A broken service worker, a lazy import that 404s, or a sheet that traps the keyboard would reach readers unnoticed.

## What

1. **Playwright (L7)** against `npm run build && vite preview`, so the real service worker and lazy chunks are tested. Four projects: Chromium desktop, WebKit desktop, Pixel 7 (Chromium) and iPhone 14 (WebKit).
2. **Critical journeys**, one spec file each (`e2e/cuj-*.spec.ts`):
   - CUJ-1 first run: onboarding → sample → first card; switch UI to English and back (closes the 0.19 debt "Settings language switch").
   - CUJ-2 paste → read 10 cards → reload → open from the library → same card (same `charOffset` in IndexedDB).
   - CUJ-3 change card length mid-text → the same sentence stays on screen; a bookmark still points to the same text.
   - CUJ-4 import `.epub` and `.pdf` → right title, right first card.
   - CUJ-5 load once, go offline, reload → library and reading work; URL import shows a calm offline message.
3. **axe-core (L8)** on onboarding, the library, the reader and every sheet, in all four themes. Fails on `serious` and `critical`.
4. **Keyboard-only journey**: Tab to every control used, read with Space / arrows / j / k, toggle with letter keys by physical code (Latin and Ukrainian layouts), open and close sheets with Escape.
5. **CI**: an `e2e` job after `checks` on every PR. `/api/extract` is mocked with `page.route`, so no test touches the network.

**Under the hood (IMP-13):** every PR uploads a Worker version (`wrangler versions upload`) and comments its preview URL on the PR, so the release checklist runs on a real phone before merge.

## Decisions

- **Fixtures are built in memory.** The EPUB is zipped with `fflate` and the PDF is a hand-written PDF 1.4 with one text object, both in `e2e/support/fixtures.ts`. No binary files in the repo, nothing copyrighted.
- **Offline URL import.** Before 0.20, a failed `fetch` (offline) showed "Couldn't get the article text", which sounds like the site's fault. CUJ-5 needs a clear message, so `extractArticleFromUrl` now throws `PlynError('offline')` when the browser is offline or the request never reaches the server. One new string per language.
- **Progress is checked in IndexedDB, not only on screen.** CUJ-2 and CUJ-3 read `charOffset` from `plyn_library_v2` through `page.evaluate`, because invariant 1 is about the offset, not the card number.
- **Speech is not exercised.** WebKit and headless Chromium have no voices; journeys don't depend on TTS (that is 0.26, CUJ-12).
- **Firefox is not in the PR matrix** (TESTING.md: weekly, later). Visual snapshots are 0.22.
- **axe exceptions.** Anything found that is not `serious`/`critical` is logged, not failed; the full gate is 0.28.
- **Preview deployments** reuse the existing `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` secrets. They run only for PRs from this repository (forks get no secrets). A preview has its own origin, so its IndexedDB never mixes with production.

## Findings

axe (serious) found, and 0.20 fixed:

- **Contrast below 4.5:1**: `--text-muted` in paper, gray and mint (hero text, char count, ghost buttons, "Skip"), the paper `--accent` behind primary buttons, the first-card hint (an extra `opacity: 0.8`) and achievement toasts in gray and mint. New values keep the same hue and pass on `--bg`, `--surface` and `--surface-elevated`.
- **Label in name** (WCAG 2.5.3): the awards and Thought Parking pills, the bookmarks count badge, the anchor button and the "Library" back button had accessible names that did not contain their visible text.
- **Nested interactive**: the library card was an `<article role="button">` with rename and delete buttons inside. Now the title is a real `<button>` stretched over the card with CSS, so a click anywhere still opens it.
- **Kept as an exception** (`e2e/a11y-exceptions.ts`): the faded tail of the previous card (`.card-context`), which is decorative and `aria-hidden`. 0.28 reviews it with readers.

Journeys also found a real loss of place: progress goes to IndexedDB with a 250 ms debounce, and a reload or a closed app within that time kept the previous card (seen in 7 of 12 runs). Approaches considered:

1. Flush the pending write on `pagehide` / `visibilitychange`. Tried: the IndexedDB transaction started during unload is often dropped (CUJ-2 still failed).
2. Write on every card change. Rejected: each write rewrites the whole document, text included, which is heavy for a long book.
3. **Chosen:** a one-entry synchronous journal in localStorage (`plyn_progress_journal_v1`, `services/storage/progressJournal.ts`) written on every card change and cleared after the IndexedDB write. On start the app applies it only if it is newer than the stored document. Offsets only, never text. CUJ-2 has a "reload right after a swipe" case.

Also added beyond the plan: an iPhone 14 (WebKit) project, and an axe pass on the English UI.
