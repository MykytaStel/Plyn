# 0.23.0 — Books import well

Status: shipped · 2026-11-26 · [roadmap entry](../../ROADMAP.md#0230--books-import-well)

## Why

A reader with a real book expects its chapters, its author, and letters that are not broken, whatever encoding an old `.txt` was saved in. Before 0.23 an EPUB lost its structure (all chapters glued into one text), the author was dropped, FB2 was not accepted, and a Windows-1251 `.txt` opened as mojibake.

## What

1. **EPUB contents.** The nav document (EPUB 3) or NCX (EPUB 2) becomes `PlynDocument.chapters`: `{ title, offset, level }`, offsets into the normalized text like bookmarks. Links with `#fragment` land on the right paragraph inside a file.
2. **Author** from `dc:creator` (EPUB) and `<author>` (FB2), shown under the title in the library and matched by search.
3. **`.txt` and `.md` in any common encoding** (`core/parsers/textEncoding.ts`): BOM, UTF-16 without BOM, strict UTF-8, then Windows-1251 vs KOI8-U by lowercase share. If unsure, UTF-8 and a calm hint.
4. **FB2** (`.fb2`, `.fb2.zip`), see EXP-04 below.
5. **No frozen screen on a big book.** Unzipping runs in fflate's workers; EPUB parsing yields between chapter files and FB2 every 400 elements.

## Decisions

- **Contents live in the bookmarks sheet**, as the roadmap says, behind a two-way switch "Contents | Bookmarks" that appears only for books with a table of contents. The header button that used to appear only with bookmarks now also appears for such books (a list icon until there is a bookmark); on phones the same entry is in "⋯". No new control on a main screen. The sheet closes on back like every other sheet (0.22).
- **Chapters are kept only if they still fit the text.** The editor shows the parsed text; if the reader edits it before "Start reading", author and chapters are dropped, because the offsets would no longer match. `sanitizeChapters` (db.ts) drops malformed entries and anything past the end of the text, on create and on backup import. Fewer than two entries are not shown.
- **Shared parser output** (`core/parsers/bookText.ts`): parsers produce clean paragraphs and markers by paragraph index; `joinBlocks` turns them into text and offsets. The joined text is its own normalized form, so offsets are valid reading positions.
- **Nested blocks.** An EPUB `<li>` or `<blockquote>` that wraps `<p>`s no longer repeats their text: only the innermost paragraph-like elements are read.
- **Backup stays `schemaVersion: 2`.** `author` and `chapters` are optional document fields; the payload shape does not change, and older versions can still import a 0.23 backup (they ignore the new fields). Fixture `spec/backups/v2-0.23.json` covers them.
- **No Dexie version bump.** New document fields are not indexed.
- **DOMParser cannot run in a Web Worker**, so "off the main thread" is done in two parts: decompression in fflate's own workers (`unzip`, with a synchronous fallback in tests or if a worker cannot start), and parsing split into chunks with `setTimeout(0)` between them.
- **FB2 details.** The prolog's `encoding` is honoured (Windows-1251 is common), otherwise the bytes are detected like a `.txt`. The `notes`/`comments` bodies and footnote marks (`<a l:href="#n1">1</a>`) are left out. Titled `<section>`s become chapters, nested by depth.
- **Golden files** (IMP-17): `spec/parsers/txt/` (one self-written text in nine encodings) with `txt-encodings.json`, and `spec/parsers/books/` (two EPUBs, two FB2s, built by `scripts/fixtures/build-book-fixtures.mjs`) with hand-written expectations in `books.json`. Both are binary on purpose: native apps must read the same bytes.

## EXP-04 decision

FB2 ships. It is a primary format in the large Ukrainian free e-book libraries, the parser is small (DOMParser and the existing fflate), and it adds no control: `.fb2` is one more accepted extension. Encoding detection meets the success criteria on the fixtures (100 %) and on 400 generated Windows-1251 and KOI8-U texts (100 %, seeded property test).
