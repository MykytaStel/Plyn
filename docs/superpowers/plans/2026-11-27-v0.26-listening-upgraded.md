# 0.26 Listening, upgraded: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The spoken word is highlighted, a voice can be chosen per content language, and auto-advance plays card to card without gaps and stops at a chapter's first card.

**Architecture:** Two pure helpers in `src/core/` (word range from a boundary event, chapter start inside a card). `services/speech/tts.ts` becomes the only place that touches `speechSynthesis`: voices, a per-card queue, word ranges and the 3 s "no word positions" rule. `useSpeech` drives the queue and the chapter stop and exposes the spoken range, `CardSlide` marks the word, and Settings gets three new rows.

**Tech Stack:** React 19, TypeScript strict, Zustand, Vitest (node + dom), Playwright.

**Spec:** [docs/superpowers/specs/2026-11-27-v0.26-listening-upgraded-design.md](../specs/2026-11-27-v0.26-listening-upgraded-design.md). Experiment: [EXP-02](../../experiments/EXP-02-tts-word-highlighting.md).

## Global Constraints

- The highlight is off by default (`ttsWordHighlight: false`), lives in Settings → Sound, and is static: background only, no transition, no change to letter or word spacing.
- Detection by behaviour, never by user agent. No word event within **3000 ms** of `start` → no highlight for that utterance, and that voice is marked for the session.
- Skip boundaries whose `charIndex` doesn't start a letter or digit. Trim trailing punctuation from the range.
- New settings fields go into `plyn_settings_v1` with defaults: `ttsWordHighlight: boolean`, `ttsVoices: { uk?: string; en?: string }` (voiceURI). No new key, and backup `schemaVersion` stays 2.
- `src/core/` stays free of DOM, React, storage and copy. No Cyrillic in `src/features/` or `src/core/` outside comments: every string goes into `uk.ts` and `en.ts`.
- No new control on a main screen. The chapter stop reuses the existing reader toast (`showToast`, `aria-live="polite"`). This replaces the spec's "line under the toolbar", and it means the same thing to the reader.
- Network voices are allowed but marked. Plyn must still work offline with the browser default.
- Commit after each task with a conventional prefix. Run `npm run lint && npm run typecheck && npm test` before each commit.

## Review Focus

1. **A manual swipe during auto-advance**: the queue must be cancelled and listening must stop; queued card N+2 must never start. Owned by Task 4 (`stops the queue when the reader turns a card by hand`).
2. **The voice list arrives late or a saved voice is missing**: `getVoices()` is empty at first on Chrome and iOS, and a saved voiceURI may come from another device. Expect the browser default, with no error. Owned by Task 3 (`falls back to the default voice when the saved one is missing`).
3. **A rate change or a new voice while speaking**: settings change mid-utterance. Expect the change to apply from the next card, with no double speech. Owned by Task 4 (`a settings change restarts nothing mid-card`).
4. **Sentence focus with a highlight**: card text split into sentences must still map character offsets right, including repeated sentences. Owned by Task 4 (`marks the right word inside sentence focus, also when a sentence repeats`).
5. **The last card and the done slide**: auto-advance at the last card must stop cleanly, with no queue past the end and no chapter toast. Owned by Task 4 (`ends after the last card without queueing`).

  export function speakSingleWord(word: string, voiceURI?: string): void;
